# MHP3rd Translation Toolkit

A translation and modding toolkit for **Monster Hunter Portable 3rd** (PSP, `ULJM-05800`) and its PS3 HD edition (`NPJB-40001`), written in Dart.

> **Status: early development (Phase 1 of 6).** The ISO reader, the `DATA.BIN` cipher/index and the `string_table_a` text codec exist and are tested on synthetic fixtures. There is no usable translation workflow yet. See [Project status](#project-status).

## What it does (target workflow)

1. Read the game ISO and locate `PSP_GAME/USRDIR/DATA.BIN`.
2. Decrypt `DATA.BIN` (LBA-dependent cipher) and index its numbered files.
3. Decode the text tables and import them into a translation database.
4. Translate (Flutter desktop app, optionally a collaborative server).
5. Check translation length (bytes, pixels, lines).
6. Re-encode, re-encrypt **at the original LBA**, produce a `MHP3RD_DATA.BIN` patch and apply it to a **copy** of the ISO.
7. Re-verify the result.

The functional specification lives in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) (in French).

## Legal notice

This repository contains **no game data**: no ISO, no `DATA.BIN`, no extracted files, no Japanese game text, no fonts, textures or screenshots. You must supply your own legally obtained copy of the game.

- Unit tests use **synthetic fixtures generated by code** only.
- Tests on real data read the path from `MHP3_ISO` (or `MHP3_DATABIN`) and are skipped when it is not set.
- The source ISO is never opened for writing; all writes go to a copy.

  mh_iso/        ISO 9660 parser, game version registry, MD5 check, cloneTo
  mh_databin/    DATA.BIN cipher, TOC, file index
  mh_formats/    format codecs (string_table_a; quest, pac, gim, font later)
  mh_budget/     length measurement (bytes / pixels / lines)      [planned]
  mh_tdb/        translation database (drift/SQLite), sync        [planned]
  mh_build/      build pipeline, cache, reports                   [planned]

  mh_cli/        `mhtk` command-line tool
  mh_studio/     Flutter desktop translation app (Riverpod)       [planned]
  mh_patcher/    standalone end-user patcher                      [planned]
server/
  mh_server/     REST + WebSocket API, PostgreSQL                 [planned]
config/          game_versions.yaml (and later control_codes, profiles)
docs/            ARCHITECTURE.md, PROGRESS.md, FORMATS/, DECISIONS/

Package dependencies are one-way (no cycles):

```
mh_binary <- mh_iso <- mh_databin <- mh_formats <- mh_budget <- mh_build
                                          ^            ^
                                        mh_tdb --------+
```

The core packages (`mh_binary`, `mh_iso`, `mh_databin`, `mh_formats`, `mh_budget`) are pure Dart with no Flutter dependency.

## Getting started

Requirements: Dart >= 3.6 (the repo was set up with Dart 3.9). Flutter via FVM is only needed for the future studio app (`pwsh scripts/setup_studio.ps1`).

```bash
dart pub get                      # resolves the pub workspace from the repo root
scripts/check.sh                  # format + analyze + unit tests, whole repo
scripts/check.sh packages/mh_formats   # same, for one package
```

When using FVM, put `.fvm/flutter_sdk/bin` on your `PATH` first.

### Tests on real data

Place your ISO under `local/` (gitignored), then:

```bash
MHP3_ISO=local/MHP3.iso scripts/check.sh packages/mh_iso --integration
MHP3_ISO=local/MHP3.iso scripts/check.sh packages/mh_databin --integration
```

### CLI

```bash
dart run apps/mh_cli/bin/mhtk.dart --help
dart run apps/mh_cli/bin/mhtk.dart index --iso local/MHP3.iso   # list files in DATA.BIN
dart run apps/mh_cli/bin/mhtk.dart index path/to/DATA.BIN
dart run apps/mh_cli/bin/mhtk.dart init --iso local/MHP3.iso --project out/fr   # create a project (MD5 checked, SQLite db)
dart run apps/mh_cli/bin/mhtk.dart extract --project out/fr                  # detect and import the text tables
dart run apps/mh_cli/bin/mhtk.dart import --project out/fr --from ./dump --file 17   # apply a mhtools dump folder to one file
dart run apps/mh_cli/bin/mhtk.dart status --project out/fr                   # files, strings, translations by status
```

`index` prints the file count, the largest slot and the sum of slots.

## Design rules

- **Never invent binary structures.** Every field, offset or algorithm cites its source (`third_party/` file and function, or `docs/FORMATS/*.md`). Unknown fields are kept verbatim (`unknownXxx`).
- **Bit-exact round trips.** `encode(decode(f)) == f` for unmodified files and `encrypt(decrypt(x, lba), lba) == x`.
- **`measure(model) == encode(model).length`**, exactly.
- **No relocation in v1.** Files are re-encrypted at their original LBA; the rebuilt size must fit the slot (`strict` policy: not larger than the original size).
- All integers are little-endian; a sector is 2048 bytes.
- Typed errors (`FormatError`, `CryptoError`, `PatchError`, `IsoError`) carry the offset and file ID.

Details for contributors and coding agents: [`AGENTS.md`](AGENTS.md).
